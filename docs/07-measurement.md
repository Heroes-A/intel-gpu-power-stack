# 07 · 测量方法：为什么读数会"跳"

> 这一篇回答一个反复出现的问题：「功耗曲线一直在 0–43 W 之间跳，是不是没做好？」
> 答：不是。**真实均值很稳，跳的是采样窗，不是设备。**

## 1. 结论先行

| 观测方式 | 结果 |
|---|---|
| 0.5 秒窗口采样（179 个样本） | 均值 8.3 W，标准差 5.0，最小 0.0、最大 19.5 W |
| 0.1 秒粒度读能量计数器 | 相邻 100 ms 增量在 0 – 5.4 J 间跳（等效 0 – 54 W） |
| **15 秒区间能量均值（落库口径）** | **8.0 – 8.6 W，波动 < 0.6 W** |
| 60 秒端点差分 | 8.45 W |

即：**平均值稳定在 8–8.6 W，瞬时值确实在跳，但没有意义**——
GPU 大部分时间处于极低功耗态，每隔若干秒短暂抬升几十毫秒到十几瓦，
用 2 秒窗口看就成了"忽高忽低"。

## 2. 逐个排除的怀疑对象

| 怀疑对象 | 实验方法 | 结果 | 判定 |
|---|---|---|---|
| 面板自身采样（2 s 读 hwmon） | 停容器 60 s 端点差分 vs 运行中 | 12.00 W vs 12.51 W | 只占 0.5 W，非主因 |
| 容器内推理进程的软件活动 | `docker pause` 冻结全部线程（fd 保留） | 8.34 / 8.41 / 8.35 W 三态一致 | **无关** |
| GPU 引擎有活干 | fdinfo 引擎占用差分 | 所有进程 0.0% | **无关（不是计算负载）** |
| 计数器量化（chunk 更新） | 0.1 s 粒度看步进 | 每次读数都在变，间隔 0.101 s | **不是量化假象，是真实波动** |
| 系统服务轮询 | 已掩藏，持卡列表只剩容器进程 | L1 驻留 88–99.9% | 已治理，非本问题 |

**物理本质**：GPU 在「深度省电态」与「短暂唤醒态」之间自行循环（`pkg` 域 1.1 W ↔ 17 W），
属于 Battlemage 显卡 PCU 的正常电源管理行为；引擎无负载，所以看不到"谁在干活"。

## 3. 测量本身会伤功耗

无人持卡（`runtime_usage == 0`）时设备处于挂起，**高频读 hwmon 会把它反复唤醒**：

| 无人持卡时的读法 | 实测 |
|---|---|
| 只读首尾两次（60 s 端点差分） | **12.0 W** |
| 每 0.5 秒读一次 | **31 W**（稳定值，std 0.09） |

0.5 秒轮询把「本可挂起的 12 W」读成了「持续唤醒的 31 W」。这是监控自身的代价，不是设备变差。

> 所以 `b60-guard` 的采样是自适应的：有人持卡 2 s 一次，无人持卡 15 s 一次，
> 面板上会显示 `采样模式：待机降频`。

## 4. 正确的测法

```bash
# 1) 用能量计数器做区间差分，窗长 ≥15 s
E1=$(cat /sys/class/hwmon/hwmon*/energy1_input | head -1); sleep 60
E2=$(cat /sys/class/hwmon/hwmon*/energy1_input | head -1)
awk "BEGIN{printf \"%.2f W\n\", ($E2-$E1)/60e6}"

# 2) 同时看 L1 驻留，确认链路真的在睡
sudo cat /sys/kernel/debug/dri/0000:03:00.0/dgfx_pcie_link_residencies

# 3) 别在测量时开一堆监控
systemctl stop <你的监控>   # 需要时临时停掉其它采样者
```

判定标准建议：

| 指标 | 健康值 |
|---|---|
| 15 s 均值 | 8.0 – 8.7 W |
| L1 驻留 | ≥90% |
| `runtime_usage` | 0（无人持卡时） |
| 整卡温度 | 稳定，无风扇狂转 |

## 5. 面板怎么处理这件事

1. **双口径显示**：主数字是 60 秒滑动均值；瞬时值与 60 s 区间（min–max）单列，
   避免被尖峰误导。
2. **历史落库**：每 15 秒写一行「区间能量均值」（能量差分天生抗尖峰），SQLite 保留 30 天。
3. **曲线降采样**：1h / 6h / 24h / 7d / 30d 五档，≤360 点。
4. **告警口径**：只看均值——持续 >25 W 超 5 分钟才告警，30 分钟内不重复刷。

瞬时值保留是为了排查（看得到尖峰的形态），主显示用均值是为了决策。两者不冲突。
